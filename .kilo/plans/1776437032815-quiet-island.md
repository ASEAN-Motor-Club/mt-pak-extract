# Plan: Adding Shooting Mechanics to Motor Town via UE4SS

## TL;DR

**You cannot add new Server RPCs to a UE5 game via modding.** UE's networking requires compile-time UHT processing to register RPCs — no runtime mechanism exists. However, since you already run UE4SS on the dedicated server with an HTTP API, you can achieve shooting via the **existing client→server communication architecture**.

---

## Why New Server RPCs Are Impossible

1. **UHT is compile-time**: Server RPCs are declared with `UFUNCTION(Server)` and processed by Unreal Header Tool at compile time. UHT generates `*_generated.h` code that registers the RPC with the engine's network replication system.
2. **No runtime registration**: The network driver's RPC mapping tables are built at cook time. There's no API in UE4SS or any modding framework to register new RPC entries.
3. **SetFunctionFlags is insufficient**: UE4SS can set `FUNC_NetServer` on an existing UFunction, but this doesn't create a network route — the driver won't know to serialize/deserialize or transmit the call.
4. **Blueprint custom events don't work**: Mod Blueprints loaded by UE4SS/UML are spawned at runtime and don't go through UHT or the network serialization pipeline. Setting "Run on Server" on a Blueprint custom event has no effect.

## Viable Approach: Existing Architecture Extension

Your mod already has the infrastructure needed. The architecture is:

```
Client UE4SS ──HTTP──▸ Server UE4SS ──calls──▸ Game UFunctions ──replicates──▸ All Clients
```

This is how ghost mode, teleport, hide costume, etc. already work. The shooting system extends this pattern.

## Implementation Plan

### Phase 1: Client-Side — Shoot Action + Hit Detection

**New file: `ClientScripts/ShootingManager.lua`**

1. **Keybind**: Register a shoot keybind (e.g., Left Mouse Button via `RegisterKeyBind` or poll gamepad)
2. **Line trace**: Reuse `GetHitResultFromCenterLineTrace()` from `Helpers.lua` (already does 50,000-unit camera raycast)
3. **On shoot**: Collect hit data:
   - Target actor (and its class: `AMTCharacter`, `AMTVehicle`, `AMTCargo`, etc.)
   - Hit location (world space)
   - Hit component
   - Player controller / character GUID
4. **Send to server**: HTTP POST to `http://127.0.0.1:5001/api/shoot` with JSON payload:
   ```json
   {
     "shooter_guid": "<character_guid>",
     "target_class": "MTCharacter",
     "target_guid": "<target_guid>",
     "hit_location": {"X": 100, "Y": 200, "Z": 300},
     "weapon_type": "pistol",
     "damage": 25.0
   }
   ```
5. **Local feedback**: Play a local sound, show a muzzle flash (widget or particle), display a crosshair HUD element

### Phase 2: Server-Side — Damage Application

**New file: `Scripts/ShootingManager.lua`** + **extend `Scripts/main.lua`**

1. **New REST endpoint**: `POST /api/shoot` — receives hit data from client
2. **Server-side hit validation** (anti-cheat):
   - Verify shooter exists and is alive
   - Verify target exists
   - Basic distance/range check (optional)
   - Rate limiting (fire rate enforcement)
3. **Apply damage based on target type**:

| Target Type | Server-Side UFunction | How to Call |
|---|---|---|
| **MTCharacter** (player) | `AMotorTownPlayerController:ServerApplyImpact` (knockback) + set health/damage directly | `ExecuteInGameThread(function() target:TakeDamage(amount, ...) end)` or modify health property directly |
| **MTVehicle** | `AMotorTownPlayerController:ServerSetVehiclePartDamage(Vehicle, PartSlot, Damage)` | Call via `PC:ServerSetVehiclePartDamage(vehicle, partSlot, damage)` — this is an existing Server RPC that the server can call directly |
| **MTCargo** | `AMotorTownPlayerController:ServerAddCargoDamage(Cargo, Damage)` | Call via `PC:ServerAddCargoDamage(cargo, damage)` — existing Server RPC |
| **Destructible** | `UGameplayStatics:ApplyPointDamage` or `ApplyRadialDamage` | Call via UE4SS UFunction invocation on the server |

4. **Broadcast visual effects**: After applying damage, set a replicated property or call a multicast to show hit effects on all clients. Options:
   - Use `ServerApplyImpact` with a small impulse for knockback + visual
   - Call `MulticastPlayHitSound` on the vehicle
   - Set a replicated "hit marker" flag that client mods detect

### Phase 3: Ammo & Weapon System

**Extend `ClientScripts/ShootingManager.lua`**

1. **Ammo tracking**: Client-side Lua table with ammo counts per weapon type
2. **UI**: Simple ammo counter widget (reuse the `StaticConstructObject` pattern from `ModManager.lua` / `SatNav.lua`)
3. **Reload**: Keybind or auto-reload with cooldown timer
4. **Weapon switching**: Cycle through weapon types (pistol, rifle, shotgun with different damage/range/fire-rate)
5. **Server-side ammo validation**: Server tracks ammo per player, rejects shoot requests when empty

### Phase 4: Visual & Audio Polish

1. **Crosshair**: HUD widget drawn via `StaticConstructObject` (UMG CanvasPanel + Image)
2. **Hit marker**: Brief widget flash on successful hit
3. **Muzzle flash**: Optional particle effect or screen overlay
4. **Sound**: `PlaySoundAtLocation` via UE4SS or widget-based audio
5. **Tracer**: Optional — spawn a temporary actor along the line trace path

## Key Game Functions Available (No New RPCs Needed)

| Function | Type | Purpose |
|---|---|---|
| `PC:ServerApplyImpact(Impact)` | **Server RPC** (callable from client) | Physics knockback on hit |
| `PC:ServerSetVehiclePartDamage(Vehicle, PartSlot, Damage)` | **Server RPC** (callable on server) | Vehicle damage |
| `PC:ServerAddCargoDamage(Cargo, Damage)` | **Server RPC** (callable on server) | Cargo damage |
| `PC:Cheat_Damage(PartSlot, Damage)` | **Server RPC** (dev cheat) | Generic damage (may need validation) |
| `Vehicle:MulticastPlayHitSound(Location, Volume, ExceptionPC)` | **Multicast** | Hit sound on all clients |
| `Vehicle:MulticastSetPartDamage(PartSlot, Damage)` | **Multicast** | Visual damage update |
| `Actor:TakeDamage(...)` | **UFunction** (callable via UE4SS on server) | Standard UE damage |
| `UGameplayStatics:ApplyPointDamage(...)` | **Static UFunction** | Point damage with full pipeline |
| `UGameplayStatics:ApplyRadialDamage(...)` | **Static UFunction** | Explosions/AOE |

## Alternative: Hijacking Existing Server RPCs

If you want to avoid the HTTP round-trip latency (~1-5ms local), you can **hijack** `ServerApplyImpact` to carry damage semantics:

1. Client calls `PC:ServerApplyImpact(impact)` with a specially-crafted impulse (e.g., impulse magnitude encodes damage amount, or use a recognized "weapon impulse" pattern)
2. Server-side UE4SS hooks `ServerApplyImpact` (pre-hook) and checks if the impulse matches a "shooting" pattern
3. If so, the server extracts the target component from the impact, finds the owning actor, and applies damage server-side
4. The normal `MulticastApplyImpact` still fires for visual knockback

**Pros**: Zero additional latency (native RPC path), no HTTP overhead
**Cons**: Fragile (relies on pattern matching), limited data bandwidth in `FMTPhysicsImpact` struct (only Component + Location + Impulse vector)

**Recommendation**: Start with the HTTP API approach (simpler, more robust), then optimize to the hijack approach if latency is problematic.

## Critical Finding: No Character Health System

`AMTCharacter` has **no health/damage property**. The game tracks:
- Vehicle part damage (`ServerSetVehiclePartDamage`, `Damage` float per part)
- Cargo damage (`ServerAddCargoDamage`, `Net_Damage` float)
- Character knockdown (`Server_Knockdown()` — Server RPC)
- Character flags (`Net_CharacterFlags` uint32 — bit 4=Ghost, bit 16=Invisible)
- Generic actor damage (`bCanBeDamaged` — boolean, used for god mode)
- Gameplay event broadcasting (`MulticastEvent(EventType)`)

**Characters cannot "die" in Motor Town** — there is no health bar, no HP, no death mechanic. The game is a driving/cargo sim, not a combat game.

## Revised Shooting Options

Given no character health system, shooting mechanics must be **invented from scratch** using available building blocks:

### Option A: Knockdown + Custom Health (Recommended)
1. **Custom health tracking**: Server-side Lua table maps `CharacterGuid → {HP, maxHP, lastDamageTime}`
2. **On shoot hit**: Server decrements HP, calls `target:Server_Knockdown()` if HP ≤ 0
3. **On knockdown**: Character ragdolls (existing game animation). After X seconds, auto-revive with full HP
4. **Visual feedback**: `MulticastEvent(EventType)` for hit notification; custom HUD for HP bars
5. **Respawn**: `ServerRespawnCharacter()` already exists — can be called when player "dies"

### Option B: Tag-Based (Paintball/Tag Mode)
1. **No health**: Each hit increments a "tags" counter on the server
2. **Score-based**: Server tracks hits per player, broadcasts leaderboard
3. **Visual**: Use `ServerApplyImpact` for knockback + `MulticastPlayHitSound` for audio
4. **Simpler**: No death/respawn needed — just a hit counter

### Option C: Vehicle Combat Only
1. **Skip character damage entirely**: Focus shooting on vehicles only
2. **Use existing damage**: `ServerSetVehiclePartDamage(Vehicle, PartSlot, Damage)` — fully supported
3. **Vehicle destruction**: When body damage exceeds `BodyDamageThreshold`, vehicle is "destroyed"
4. **More natural**: Vehicle damage is already a game mechanic; shooting just applies it from range

### Option D: Stun/Slow Effects
1. **No health/damage**: Hits apply debuffs via `Net_CharacterFlags` bit manipulation
2. **Slow**: Could modify character movement speed property
3. **Stun**: `Server_Knockdown()` for brief stun effect
4. **Timed effects**: Server tracks debuff duration, auto-removes after timer

## Recommended Implementation: Option A (Knockdown + Custom Health)

This gives the most "FPS-like" experience while working within the game's constraints:

1. **Health**: Tracked entirely in server-side Lua (not a UE property — no replication issues)
2. **Damage**: Via HTTP API from client → server, server decrements HP
3. **Knockdown**: `Server_Knockdown()` when HP ≤ 0 (existing Server RPC, no new RPC needed)
4. **Revive**: After 5 seconds, server auto-restores HP and character gets up
5. **HUD**: Client-side HP bar widget (UMG CanvasPanel pattern from SatNav.lua)
6. **Hit markers**: Client-side widget flash on successful hit
7. **Scoreboard**: Server tracks kills/deaths, REST endpoint for leaderboard

## Open Questions

1. **`Server_Knockdown()` behavior**: Does this actually ragdoll the character? How long does the knockdown last? Need to test in-game.
2. **`EMTCharacterEventType` enum values**: What event types exist? Could one represent "hit" for `MulticastEvent()`?
3. **HP sync frequency**: Polling `/api/health` vs. pushing HP updates via a dedicated websocket/SSE channel.
4. **Fire rate / ammo balance**: Game design decisions — damage per hit, fire rate, max HP, revive time.
5. **Vehicle vs. character shooting**: Should both be supported from the start, or start with characters only?
