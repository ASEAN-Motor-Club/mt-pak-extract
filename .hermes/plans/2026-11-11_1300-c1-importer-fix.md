# C1 — importer review: findings and fix plan

Date: 2026-11-11 13:00 (+07)
Scope: `c1/scripts/import_split.py`, `c1/scripts/apply_slotmap.py`,
`c1/scripts/apply_nc_materials.py`, `c1/tools/build_meshpak.sh`, `c1/tools/build_mappak.sh`.
Status: PLAN ONLY. Nothing here has been run against the editor or the client.

---

## 1. What is actually broken (evidence, not inference)

All numbers below came from the shipped artifacts (v15 paks / cooked v15 tree) or the
import report `D:\c1imp_report.json` from the run that built them.

**B1 — the import gate verifies memory, not disk.**
`import_split.py:139-179` binds materials, saves, then `slots_state()` (`:204-207`)
re-reads the same in-memory UObject (`load_asset` returns the cached package). The gate
`nc()` at `:354-364` therefore certifies `bound 219/219` for paint and `all_bound` for
foliage while the cooked assets had **every slot on WorldGridMaterial (import index -5)**.
Two shipping bugs came out of this hole: v13 (all meshes, no materials) and v14/v15
(NC layer invisible).

**B2 — the structural collision flag never persists, but NC collision is already correct.**
Report: all 555 cells `flag = CTF_USE_COMPLEX_AS_SIMPLE (3)`.
Cooked asset (`Meshes/c-13_-28.uasset`) **and the project asset**: `CollisionTraceFlag (Byte): 0`
= UseDefault, with `ConvexElems (Array[1])` of 30 vertices. So the editor write at
`import_split.py:260-262` never reaches disk either — this is not a cook problem.

Runtime probe (UE4SS, `NCPROBE`, 792 StaticMeshActors) settles the part that matters:

- NC actors: **`profile=NoCollision`** (3/3 sampled) — the sublevel authoring already
  disables them at the component level, which is the level that governs a placed actor.
  The split works; my earlier "NC probably still collides" was wrong.
- Cell actors: `profile=BlockAll`, and with flag 0 both representations are live: complex
  traces read the triangles (that is why driving works), cheap queries read the 30-vertex
  hull that spans a whole cell.

So the remaining flag issue is *not* about collision being broken. It is that the report
claims a setting the asset does not have, and cheap traces (line-of-sight, overlaps,
sweeps, possibly AI probes) see a kilometre-wide blob instead of geometry.

Note `ECollisionTraceFlag` has no "none" value (`PhysicsCore_enums.lua:16`):
UseDefault 0 / UseSimpleAndComplex 1 / UseSimpleAsComplex 2 / UseComplexAsSimple 3.
Disabling is a different axis, `ECollisionEnabled.NoCollision`, or a `NoCollision` profile
— which is what the NC actors already use.

**B3 — `empty_source()` cannot detect the case it documents.**
`:70-87` calls a file empty only if no `f ` line has >= 4 tokens. The placeholder it
describes (`f 0 1/1/1 2/2/2`) has exactly 4 tokens, so the guard answers "not empty" and
the placeholder imports as a one-triangle mesh. 51 OBJs are under the 8 KB threshold and
carry real geometry (1-21 faces), so the threshold alone cannot separate them either.
Nothing compares a cell's face count against the split report, so a *truncated* cell is
indistinguishable from a genuinely small one.

**B4 — five cells exist in the source tree but are never placed. RESOLVED — not a bug.**
`c-14_-21`, `c-16_-25`, `c4_-4`, `c4_9`, `c6_4` are imported into the project but absent from
every cooked tree (550 meshes vs 555 OBJs, in v12 as well as v15). Runtime probe on the live
map: **792 StaticMeshActors, 0 with a null mesh** — every placed actor resolves a mesh. The
five are simply not referenced by the level; they are leftover OBJs in the source tree, not
invisible actors in the map. No fix required.

**B5 — destructive ordering, no rollback.**
`drop()` (`:90-95`) deletes the asset before the import; a mid-run failure leaves cells
missing while each per-cell report line still looks sane.

**B6 — the config is trusted blindly.**
`load_cells()` (`:210-229`) lets `import_split_cfg.json` redirect every source path. This
is how a stale `nc_out_fixed` replaced the real source and the gate still printed OK.

**B7 — two smaller holes.**
- `apply_slots` (`:160-168`) guesses `MI_C1_<name>` for slots the slotmap does not know;
  for structural cells that can bind a different variant than shipped, and the gate
  compares slot *names*, not MI identity, so it passes.
- `import_obj` (`:61-65`) applies the x100 scale only if one of two holders exposes
  `import_uniform_scale`; if neither does, the import silently runs at 1.0 and nothing
  checks bounds afterwards.

Verified as **not** broken: slot order/count integrity. For 12 sampled cells the OBJ's
materials-with-faces count equals slotmap `want_slots` exactly (7/7, 75/75, 8/8, ...), so
`apply_slotmap`'s array restoration is not shifting faces onto the wrong materials.

## 2. Acceptance criteria

A build is only good when, measured on the **cooked** tree (what ships), not in the editor:

1. every one of the 238 NC placed actors reports `profile=NoCollision` at runtime (already
   true, sampled 3/3) and zero AggGeom on the asset;
2. every cell: `CollisionTraceFlag` on disk is recorded as what it is — either 3 persists,
   or the report stops claiming 3;
3. every NC asset: slot count > 0, non-null slots == slot count, and the material imports
   are `MI_C1_*` (zero `WorldGridMaterial` imports);
4. structural cells: non-null slots == slotmap `want_nonnull`;
5. cooked mesh count equals the number of cell actors the level references;
6. `build_meshpak.sh` refuses to produce a pak when any of 1-5 fails.

## 3. Fixes

### F1 — move the gate to the cooked artifact — **DONE (commit 03cffee)**

New `UAssetTool --verify-mesh-pak <cooked-root> [slotmap.json] [report.json]` parses the
cooked files off disk and asserts: every asset has slots; no slot sits on
`WorldGridMaterial`; NC assets have every slot bound; cells match `slotmap.json` exactly
(slot count and bound count). `c1/tools/verify_cooked.sh` wraps it (correct CWD for
`Mappings.usmap`), and `build_meshpak.sh` runs it on the **staged** tree and refuses to
pack (exit 7). `ALLOW_UNBOUND_MATERIALS=1` is the deliberate forensics escape hatch.

Proven against both trees:

- cooked v15 → `VERIFY_MESH_PAK OK checked=787 nc=237 failed=0` (rc 0)
- cooked v14 → `VERIFY_MESH_PAK FAIL checked=787 nc=237 failed=238` (rc 1);
  `build_meshpak.sh` aborts with rc 7 and writes no pak
- v15 rebuild through the gate → `MESH_PAK_OK 600633753 5e70b268`, identical to the
  shipped pak

The editor-side readback stays as a smoke test only.

### F2 — make the collision story true (kills B2)

Downgraded after the runtime probe: NC collision needs **no work** — the placed actors are
already `NoCollision`. What remains is truth-telling and one open tool bug.

- Stop the report claiming `flag=3`. Either make the write real, or record what is on disk.
- **Tool bug found while probing:** `UAssetTool --patch-export-props` reported
  "Applied export property patches" and wrote a **byte-identical file** for a
  `BytePropertyData` target, because `SetNumericProperty` had no byte case. Fixed in
  `csharp/UAssetTool/Program.cs` (added `case BytePropertyData`). Verified working for a
  `Name` property (`DefaultInstance.CollisionProfileName` -> `NoCollision` really lands in
  the file); the byte path still does not take effect on `CollisionTraceFlag`, so the
  editor-save and tool-patch routes both need one more investigation before we rely on
  either.
- Decide whether a single 30-vertex convex hull per cell is acceptable for cheap traces.
  If yes: document it and drop the claim. If no: pursue `UseComplexAsSimple` until it is
  verifiable in the cooked asset (F1 gate makes that a hard requirement).

### F3 — make `empty_source` mean something (kills B3) — **DONE (commit 5e7d3b4)**

`source_stats(path)` replaces the token-counting guess: a face is real only with three or
more corners and no 0-based index (OBJ is 1-based); rejected lines are counted so the report
reads `placeholder_faces=N`; the 8 KB shortcut is gone (large files are sampled only after
real faces appear). Degenerate sources — importable, but only a handful of triangles — are
the shape the old failure hid in, so cells with 1..15 faces are listed in
`report["low_face_cells"]`, and `report["empty_cells"]` names the skips explicitly.

Proven by a unit harness (placeholder → empty; one real face → not empty; mixed → faces=2,
bad=1; big → sampled) and, critically, the old guard provably answered *not empty* for the
placeholder.

Checked against the live source tree: struct 555 files, **0 empty, 32 low-face**; foliage 237
files, **0 empty, 31 low-face**. The placeholder trap is not firing today — the split now
writes a valid single triangle instead of a 0-based line — but **63 sliver sources** exist,
including `c-14_-21` and `c-16_-25` at one face each: two of the five cells that are imported
and never placed. They are placeholders in practice, and are now visible in the report instead
of looking like ordinary cells.

### F4 — the five missing cells (kills B4)

Cheap probe first: for one of them, read the level actor's `StaticMesh` property and see
whether it points at `/Game/Mods/C1Full/Meshes/c4_-4`. Then decide:

- if the level references a mesh that is not cooked → the cook is dropping it for a reason
  (LOD count? zero render data?) and we chase that;
- if the level does not reference it → the five are simply not in the map and the report's
  555 should be 550; document it and stop counting them.

F1's AC5 makes this fail the build until it is resolved, which is the point.

### F5 — import without losing the old asset (kills B5) — **DONE (commit ae9712c)**

`drop()` stays (it is what rebuilds the LOD chain cleanly), but every deletion is written with
the source that can rebuild it to `D:\c1_deleted_ledger.json`, reset at the start of each run.
The first import failure raises `Abort` — logged as `A4_ABORT`, no report written — instead of
`continue`-ing to the next cell and leaving that one deleted with nothing in its place. A stale
report from the previous run is deleted at start so it cannot be read as this run's result.
`C1_RESTORE=1` re-imports exactly what the ledger records.

### F6 — config fingerprint (kills B6) — **DONE (commit ae9712c)**

`validate_config()` requires `expect_struct_objs`, `expect_struct_bytes`, `expect_nc_sources`
(and optionally `expect_total_tris`) and checks them against the tree before anything is
deleted. `C1_FINGERPRINT=1` prints the block. Installed on the live tree: **555 files,
2,982,517,771 bytes, 238 nc sources, 9,120,748 faces**. This is the check that would have
stopped the `nc_out_fixed` build, where the config pointed at a directory that existed but was
not the right one.

### F7 — small ones — **DONE (commit ae9712c)**

- `apply_slots(..., allow_guess)`: structural cells no longer fall back to guessing
  `MI_C1_<slot>`; a name the slotmap does not know stays unbound and fails the gate. The NC
  passes may still guess (apply_nc_materials rebinds them), but guesses are recorded in
  `slot_guessed` and counted in `slot_guesses`.
- `check_bounds()`: after import the asset's extents must match the OBJ's within 5% per axis,
  so a silently-dropped `import_uniform_scale` (mesh 100x small) fails the cell instead of
  shipping. Part of the structural gate now.

## 4. Sequencing (one change per install window)

**Window A — collision semantics (F2 + F1).** Mesh pak v16. User-visible (NC meshes stop
colliding, if they currently do). Includes the persistence probe and the new gate.

**Window B — importer hardening (F3, F4, F5, F6, F7).** No pak needed unless F3/F4 changes
geometry; if they do, it folds into Window A's rebuild. Tooling + one import run.

Rationale for the order: F2 cannot be trusted without F1, and F1 is what stops every
future silent-material bug. F3-F7 are correctness of the pipeline, not of this build.

## 5. Risks and rollback

- **F2 risk**: CTF_NoCollision on the paint mesh could make the road surface's visual
  markings non-collidable *and* remove any collision they were providing on kerbs. The
  cells keep complex collision, so drivable geometry is unaffected; the split's own
  objective says paint carries no collision.
- **F1 risk**: a strict gate can block a build for a cosmetic mismatch. Mitigation: the
  gate prints per-asset detail and has an explicit `--allow <asset>` escape recorded in the
  release manifest, so exceptions are visible rather than silent.
- **Rollback**: paks are versioned in `releases/c1/pakset_v*`; the previous mesh pak is
  always preserved in `D:\paks_retired`. Reverting is a file swap plus a whitelist reseed.
