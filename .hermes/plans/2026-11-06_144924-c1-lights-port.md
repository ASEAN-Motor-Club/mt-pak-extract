# C1 lights — port plan (performance-gated)

> **For Hermes:** implement task-by-task in this worktree. Do not skip P0; the primitive choice
> is the whole performance story.

**Goal:** give the ported C1 map the source map's night lighting (1,470 corridor street lamps +
343 tunnel lights) without adding measurable frame time.

**Architecture:** posts are already baked into the ported cell meshes — the port needs *light*
only. Lights are our own cooked Blueprint (`BP_C1_Lamp`, lives in `Content/Mods/C1Full/`) plus one
manager actor that toggles only nearby lamps at night, so per-frame cost stays bounded by what
one player can see, not by the 1,813 lamps in the level.

**Tech stack:** UE 5.5 editor-over-pythonscript on the Windows box — **`D:/C1FullMirror`
(`MotorTown.uproject`)**, the only project that cooks `Mods/C1Full` — repo pipeline `c1/pipeline/00..09`, cook → pack → staging.

## Context (all verified, 2026-11-06)

- **Source**: `c1/tools/extract_source_lights.py` → `c1/source/c1_source_lights.json`, doc
  `c1/docs/C1_SOURCE_LIGHTS.md`. 10,474 light actors; **2,169 inside the 74-cell corridor**
  (1,470 street, 343 tunnel, 356 sign).
- **Lamp recipe (8,087 street lamps, uniform)**: SpotLight, range **20 m**, brightness 2,
  amber `rgb(1, 0.39, 0)`, inner **25°** / outer **170°**, `shadowSoftness 0.5`,
  shadow `texSize 32`. Tunnel: same but inner **90°**, texSize 256.
- **All 10,474 are authored `isEnabled: false`** — the source lights the map at night from its
  light-group system. Day-time parity is the *source* behaviour, not an optimisation.
- **Posts need no porting**: the nine `streetlamps/lightgroupN` groups contain 8,087 `SpotLight`
  and **zero `TSStatic`** — the posts are part of the terrain/road mesh that became the 554 cell
  meshes, and lamp-lens materials are already in the port's MI set
  (`c1/docs/MATERIALS_ALPHA_BLEND.md:236`).
- **The port has zero lights today**: the `C1Full` level dump (718 actors) has no
  SpotLight/PointLight actor at all.
- **Local density (corridor street+tunnel, 1,813 lamps)**: neighbours within 20 m — median **3**,
  p90 9, p99 16, max **17**. That max is the number that decides frame cost, not the total.
- **Thinning options** (greedy minimum separation): 12 m → 1,173 lamps; **17 m → 956**;
  25 m → 686.
- **MT's own lamp BPs** (`/Game/Objects/Light/*`): `_Base_Light_C` is an `AStaticMeshActor` with
  `MTComponentLOD`, `bIsTurnedOn`, `LightMaterialIndex`, `RegisterDistance` and a `RollingTick`;
  `_Base_BreakableLight_C` adds `AMTBreakable`. `InvisibleLight_Base_C` is a bare `AActor` with
  **no** `RegisterDistance` — i.e. always-on. MT's culling mechanism is `RegisterDistance` +
  `MTComponentLOD`, and it is not exposed to a bare project.
- **Blocking constraint**: we cannot place *instances* of game BP classes from the C1FullMirror
  project — a dummy-backed class instance ships as an export of the dummy and the game dies on
  load (`RF_NeedLoad`; `motortown-ue-project-map-authoring`). Native classes
  (`AMotorTownRoad`, `AMTAIVehicleSpawnSystem`) and **our own** BPs are safe. So MT's
  `Streetlamp_*` / `SpotLight_01` are out as placeables; the light primitive must be ours.

## Performance design

1. **No post geometry added.** 0 extra draw calls for the 1,470 lamps.
2. **One actor per lamp, one `SpotLightComponent`.** No shadow maps: `cast_shadows = false`,
   matching the source (texSize 32 / softness 0.5 = the source had no crisp shadows either).
3. **Movable + distance-gated, not always-on.** `BP_C1_Lamp` starts with its light off. One
   `BP_C1_LightManager` actor re-evaluates on a **0.5 s timer** and enables only lamps within
   **150 m** of the local player (and only when it is night). Everything else keeps an invisible,
   zero-cost component.
4. **Hard budget, measured, with a pass/fail:** ≤ **+1.5 ms** frame time at each checkpoint vs
   the current build at the same viewpoint and time of day, and `stat scenerendering` **Lights
   ≤ 30** at every checkpoint. Day-time parity must be inside noise.
5. **Levers in order if the gate fails**: thinning 17 m → 25 m (956 → 686 lamps), attenuation
   2000 → 1200 cm, manager radius 150 → 80 m, drop tunnel-bore duplicates. Turn intensity down
   before adding geometry tricks — the source is 20 m and dim.

## Blocking: the parent-map recook reverts P22

Everything in the shipped parent map that the light link requires a recook for was applied to the
**cooked bytes**, not to the editor project — PlayerStart moved to Shibaura, the two
`BP_C1_Prop` garages (`--clone-actor`), and the 180° rotation on all three placed actors. A recook
of `C1Full.umap` from `D:/C1FullMirror` produces the *source project's* map and drops all of it.

Order of operations is therefore not optional:

1. recook the parent map with the `C1Full_Lights` streaming link (task 9),
2. run `repair_class_refs.sh` for the cook-drop trap,
3. **replay the three P22 edits** with `c1/scripts/apply_map_edits_p22.sh` (same
   `--move-actor` / `--clone-actor` ops, same coordinates and yaws),
4. verify before packing: actor census +3, `Shibaura` at `(110237, -470902, 87411)`,
   `Tatsumi` at `(593234, -466784, 87449)`, yaws `90/90/75.57`,
5. only then pack the link pak.

Skipping 3–4 ships a map that spawns in the wrong place with one garage. Verify by reading the
`.uexp` back (double-precision positions), not by eyeballing the editor.

## Packaging — lights ship as their own pak

Measured from the shipped consolidated pak `zzz_AMC_Shuto_P.pak` (2026-11-06, 697,691,828 B,
sha256-16 `7c1ede80e752cb1e`):

- `Maps/C1Full.umap` 210,908 B + `C1Full.uexp` 181,185 B — the parent map, **~392 KB**
- `Maps/C1Full_Roads.umap` 49,140 B + `C1Full_Roads.uexp` **60,296,506 B** — the roads sublevel,
  where stage 2/4 actors live
- geometry+everything pak: single file, 697,691,828 B (the old 6-pak split is gone)

Facts that decide the shape:

1. **There is no "actors only" pak.** Actor placement lives inside a level package; any pak that
   adds actors must carry a `.umap`/`.uexp` pair. Nothing can inject actors into an already-shipped
   level.
2. **A sublevel pak works.** The port already streams `C1Full_Roads` from the parent map, so the
   engine resolves sublevel paths from mounted mod paks. A new `C1Full_Lights` sublevel can be
   cooked into its own `zzzzz_..._P.pak` that sorts after the geometry pak.

**Chosen: `C1Full_Lights` sublevel + its own pak.**

| route | one-time cost | per-iteration cost | risk |
|---|---|---|---|
| override `C1Full_Roads` (lights in the existing sublevel) | none | **60.3 MB** per build | ships nav/spawner drift with every light tweak; 4 ladder builds = 241 MB uploaded |
| **new `C1Full_Lights` sublevel** | one parent-map rebuild (392 KB pak) to carry the streaming link **+ P22 edit replay** | **~1–2 MB** per build | link must be authored in the editor, never byte-surgery (cooked `UWorld` sublevel block is per-world and corrupts) |
| client-side UE4SS Lua that spawns the lamps | — | — | every player must install a Lua mod; not a pak |

Implementation notes:

- The **parent map rebuild is a one-off**: author in `D:\C1FullMirror` (the project that cooks
  `Mods/C1Full`), `LevelEditorSubsystem.new_level` for the empty `C1Full_Lights` asset →
  `EditorLevelUtils.add_level_to_world(world, path, LevelStreamingAlwaysLoaded)` → persist with
  `EditorAssetLibrary.save_asset(MAP, ...)` (`save_current_level()` saves the wrong level) →
  cook → **`repair_class_refs.sh`** (a fresh cook drops `ChildActorClass` on the sky,
  `DefaultGameMode`, `GarageActorBP`) → **replay the P22 edits** (see the blocking section) →
  verify the map file on disk contains `LevelStreamingAlwaysLoaded` + the sublevel name before
  packing.
- **The cook needs the dependency PATH** or it exits in ~20 s with
  `The game module 'MotorTown' could not be loaded` / `Failed to load UnrealEditor-MotorTown.dll
  (GetLastError=126)` even though the DLL exists — prepend the game's
  `...\Motor Town\MotorTown\Binaries\Win64` and every `D:\C1FullMirror\Plugins\*\Binaries\Win64`
  to `$env:PATH`. Working template: `c1/tools/cook_server_c1full_v2.ps1`.
- All lanterns go in the lights sublevel; **stage 4b authors there, not into `C1Full_Roads`**.
- `BP_C1_Lamp` / `BP_C1_LightManager` cook into the same pak under
  `Content/Mods/C1Full/Blueprints/` (few KB), so one pak carries behaviour + placement.
- Iteration loop after the one-off: stage 4b (row count) → `-run=Cook -map=<lights sublevel>` →
  pack only `Maps/C1Full_Lights.*` + `Blueprints/BP_C1_*` → deploy. No geometry, no geometry-pak
  re-upload, and pulling lights = shipping an empty/absent lights pak.
- Cost of the one-off: the parent-map pak (~392 KB) must be installed **after** the current
  geometry pak. Name it `zzzzz_AMC_Shuto_Lights_link_P.pak` — `zzzzz_` sorts after `zzz_AMC_Shuto_P.pak`
  (`_` = 0x5F < `z` = 0x7A), so the link wins the mount. Lights content pak:
  `zzzzz_AMC_Shuto_Lights_P.pak`, same band, must sort after the link pak. Record the sha256-16 of
  both.

## P3 — The performance gate

### Task 11: measurement protocol
**Objective:** one repeatable measurement anyone can re-run.
**Files:** create `c1/docs/C1_LIGHTING_BUDGET.md` with the protocol; keep the raw logs under
`c1/out/light_budget/<build>/`.
**Protocol**
- Client: fixed machine and GPU (record which — Meehoi's or the Windows guest), 1080p,
  `r.ScreenPercentage 100`, `t.MaxFPS 0`, vsync off.
- Time of day: **night** for the light comparison, **noon** for parity.
- 3 checkpoints from the placement table: the spawn cell (`c3_13`), a tunnel bore
  (`tunnel_lights`, cell `0_16`), and the densest interchange cell (the one containing the
  17-lamp cluster).
- Per checkpoint: `-ExecCmds="stat unit,stat scenerendering,stat rhi"`, 60 s standing still,
  3 runs; report median frame time, worst 1 % frame, `Lights` count.
**Verify:** baseline (current build) captured for all 3 × 2 times of day and stored.

### Task 12: the ladder
**Objective:** find the knee instead of guessing.
**Builds:** 0 (baseline), 200, 500, 956 lamps. Each build is one stage-4b run with a reduced row
count → cook the **lights sublevel only** → pack the **lights pak only** (≈1–2 MB, never the geometry
pak).
**Accept:** at 956 — frame-time delta **≤ +1.5 ms** at all three checkpoints, `Lights ≤ 30`,
worst-1 % frame no worse than +3 ms, and **noon parity** within +0.2 ms.
**Verify:** table in `C1_LIGHTING_BUDGET.md` with all four builds and a verdict line
`BUDGET PASS` / `BUDGET FAIL → lever <n>`.

### Task 13: apply the levers if it fails
In order, one build each, re-measuring only the failing checkpoint:
1. thin to 25 m (686 lamps) 2. attenuation 2000 → 1200 3. manager radius 150 → 80 m
4. tunnel internal lamps → one per 40 m
Stop as soon as the gate passes; record which lever was applied.

## Risks

- **BP instance trap** — the reason the primitive is our own BP. If `BP_C1_Lamp` ever ends up
  parented to a game BP, the cook resumes emitting dummy-backed instances and the map dies on
  load. Guard: after the first cook, dump the map and assert **zero** exports named
  `Streetlamp_*`/`SpotLight_01*`.
- **Blueprint API in `-run=pythonscript`** is the flakiest part of UE 5.5 authoring; a hand-made
  BP `.uasset` committed once may be cheaper than a script that fights `BlueprintEditorLibrary`.
- **955 manager iterations at 2 Hz is nothing; 956 actors at BeginPlay is not.** `GetAllActorsOfClass`
  once at BeginPlay on a level with 554 meshes is fine, but if MT's own spawner actors also tick,
  budget the manager at 1 Hz.
- **Cook is per-level** — authoring lights into a sublevel that is not cooked ships nothing.
  `05_cook.ps1` must name the map that holds the light actors.
- **Z-snapping against OBJ triangles** can pick a tunnel roof instead of a road deck; the
  `|dz| > 2 m` warning is the guard, and tunnel lamps should snap to the bore ceiling, not the
  floor — handle `tunnel_lights` with an explicit ceiling bias (+/−60 cm below the ceiling).
